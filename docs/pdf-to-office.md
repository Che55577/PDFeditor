# PDF 轉 Office：實測與決策

一句話結論：**LibreOffice 那條路是死的，pdf2docx 可用但要背 100 MB，
而多數人真正要的其實是 Markdown。**

以下數字皆為基準語料實測結果，重跑方式見 `bench/`。

## 一、PDF → Word

同一份 100 頁中文 PDF（`bench/corpus/c1_text.pdf`，原始 0.16 MB）：

| | LibreOffice 26.2 | pdf2docx 0.5.13 |
|---|---|---|
| 耗時 | 46.3 秒 | **27.6 秒** |
| docx 大小 | 255 KB | **70 KB** |
| `document.xml` | 9,937 KB | **1,117 KB** |
| 段落 `<w:p>` | 8,700 | 566 |
| **浮動文字方塊 `<w:txbxContent>`** | **8,600（98.9%）** | **0** |

### LibreOffice 為什麼不行

它的 PDF 匯入預設進 **Draw** 模組——連 docx 匯出濾鏡都沒有，直接轉會得到
`no export filter ... found, aborting`，必須強制指定 `--infilter="writer_pdf_import"`
才轉得出來。

而產出的東西是：**原文每一個視覺行變成一個絕對定位的文字方塊**。8,600 個文字方塊
對應 100 頁 × 約 43 行。這代表打字不會把後面的文字推下去，改一個字整段版面就散。
而且 `document.xml` 從 0.16 MB 膨脹到 9.9 MB，**62 倍**。

這不是調參數能改善的，是 LibreOffice 的 PDF 匯入架構決定的。

### pdf2docx 的實際表現

零文字方塊、真段落——把每頁 42 行併回約 5.7 個段落，確實在做段落重建。
圖文混排的檔案（20 頁）：21.1 秒、117 段、0 文字方塊、**20 張圖片全部正確內嵌**。

## 二、表格偵測（決定 PDF → Excel 值不值得做）

語料帶標準答案，準確率是算出來的（`bench/make_tables.py` 產生，`bench/table_bench.py` 評分）：

| 語料 | 偵測到幾個表格 | 不做後處理 | 接合後 |
|---|---|---|---|
| 有完整框線 | 1 | 100% | 100% |
| **無框線，只靠對齊** | 1 | **100%** | 100% |
| 含合併儲存格 | 1 | 100% | 100% |
| **跨頁（40 列）** | 2 | 68% | **100%** |

無框線表格 100% 是意料之外的好結果——那是從文字座標推斷欄界，一般認為是難題。

跨頁表格被拆成兩個是**自然行為**，pdf2docx 看到的就是兩塊。把欄數相同的相鄰表格接起來、
丟掉每頁重複的標題列，就能還原到 100%。這段接合邏輯約 20 行。

### 這份數據的界限

語料是 reportlab 產生的乾淨數位 PDF。**下列情境完全沒有量到**，不要把上面的數字外推過去：

- 掃描件（需要先 OCR）
- 儲存格內文字換行、跨列
- 巢狀表格
- 旋轉頁面
- 手寫表格線歪斜

## 三、部署成本

pdf2docx 是 Python 的，執行期需要：

| 套件 | 大小 |
|---|---|
| cv2（OpenCV，表格線偵測） | 112.0 MB |
| PyMuPDF | 52.7 MB |
| numpy（含 numpy.libs） | 53.1 MB |
| fontTools | 15.7 MB |
| lxml | 8.8 MB |
| python-docx | 2.3 MB |
| 內嵌 CPython | 約 15 MB |

未壓縮約 260 MB，NSIS 壓縮後估計 **110–130 MB**。主安裝檔目前是 20.8 MB。

`cv2` 換成 `opencv-python-headless` 可省下約 70 MB，值得試。

## 四、決策

| 項目 | 決定 |
|---|---|
| PDF → Markdown | **做在主程式裡**。多數人要的只是把文字拓出來，成本是 Word 路線的十分之一 |
| PDF → Word | **做成獨立離線擴充包**。主安裝檔維持 20.8 MB，要用的人才裝 |
| PDF → Excel | **做**。表格偵測準確率夠高，且與 Word 共用同一個擴充包 |
| PDF → PowerPoint | **不做**。沒有開源方案做得好；iLovePDF 的作法是每頁轉圖再疊文字框，價值很低 |

擴充包是「使用者自行下載安裝一次」，不是執行期連網取件——**不影響「處理過程不連網」的宣稱**。

## 五、主程式版 Markdown 的已知限制

主程式不含 Python，文字抽取走 Ghostscript 的 `txtwrite` 裝置。實測中文編碼正確、
而且保留水平縮排，但**它不輸出字級**。

沒有字級就無法可靠判斷標題層級，所以主程式版的 Markdown 只做到：段落重組（消除硬換行）、
清單偵測、以及依縮排與行長推測的標題候選。要正確的標題層級，得走擴充包。

這個限制要寫在界面上，不要讓使用者以為拿得到完整的文件結構。
